# 论文池：接收外部 Agent 推荐

论文池是正式 Library 之前的候选区。Agent 可在应用运行时通过 MCP 提交，外部程序也可离线生成 JSON 文件；用户审阅后点「入库」，才会创建正式论文条目。

## 选择冷存储地址

广场 → **论文池** → 右上角 **存储地址**：

- **本地／共享／同步目录**：外部程序向目录写 UTF-8 `.json` 或 `.jsonl` 文件。可使用网盘同步目录、NAS 挂载目录或团队共享盘。
- **静态 HTTP(S) JSON 地址**：应用只 GET 该文件。例如对象存储或代码仓库发布的 JSON 快照；上传和更新由存储平台及外部程序负责。

直接读取文件不需要额外服务。通过 MCP 提交时需保持应用运行并接入工作区工具。默认目录是 `$XDG_DATA_HOME/edda/paper-pool`（Unix 默认 `~/.local/share/edda/paper-pool`）。不同机器上的实际挂载路径可以不同，但必须指向同一份共享内容。

应用启动并打开 Vault 时预读，进入论文池时按需读取；外部投递后也可点刷新。不会定时替用户运行推荐 Agent。

## 推荐数据格式

存储地址对话框可复制完整 JSON 示例。推荐使用版本化批次：

```json
{
  "schemaVersion": 1,
  "papers": [
    {
      "title": "填入真实论文标题",
      "authors": [
        { "name": "作者姓名", "affiliations": ["论文所列单位"] }
      ],
      "year": 2026,
      "abstract": "论文摘要",
      "doi": null,
      "arxivId": null,
      "url": "https://example.org/paper",
      "pdfUrl": null,
      "recommendation": "为什么值得用户阅读，与研究问题或实验的具体联系",
      "source": "Codex",
      "recommendedAt": "2026-09-18T08:00:00Z",
      "tags": ["研究主题"]
    }
  ]
}
```

标题和推荐理由必填。DOI、arXiv ID、作者单位等未知时留空，不猜测；`year` 是发表年，`recommendedAt` 是推荐时间。DOI 可用 DOI URL，arXiv ID 会去掉版本后缀。也接受单篇对象、对象数组和每行一篇的 JSONL。

## 自动化投递

在运行的应用中打开本地 Vault，按 [MCP 接入说明](mcp.md) 连接外部 Agent。
使用 `pool_example` 获取文档格式，再调用 `pool_submit`：

```json
{"document":{"schemaVersion":1,"papers":[]},"by":"Codex"}
```

将 `papers` 填成上文的真实推荐。`pool_list` 可读取结果；地址自动使用应用设置，
无需指定命令行路径。HTTP 静态来源只读，提交需要配置本地/共享目录。
提交对完整批次先验证，再原子发布一个内容寻址文件。多个 Agent 可以并发投递；
重复提交同一批次不会产生重复文件。外部程序也可先写临时文件再重命名为 `.json`。

给外部定时 Agent 的任务示例：

> 为我的研究方向筛选论文，核对标题、作者、单位、摘要和 DOI/arXiv。为每篇写出与当前研究的具体关联及推荐理由，记录来源和推荐时间。按论文池 v1 格式调用 MCP `pool_submit` 提交。只进入候选池，是否加入正式论文库由我审阅决定。

## 浏览与转正

- 表格显示标题、作者、单位、摘要、推荐理由及 DOI/arXiv；点击标题展开完整内容。
- 搜索覆盖这些字段和来源名称。
- 相同 DOI 或 arXiv 的推荐合并，保留各来源理由。缺少标识符时按标题、首作者和年份精确归并，不做模糊合并。
- 默认显示待入库项；「包含已入库」可查看全部。状态以**当前 Vault**为准，共享池的其他使用者不受影响。
- 点「入库」复用正式入库流程，将题录和笔记壳平级写到 `papers/`。metadata 的 `extra` 字段以 JSON 字符串保存 `eddaPaperPool`，包含作者单位、推荐理由和来源。
- 入库不改动冷存储、不自动下载 PDF；之后可在 Library 下载或添加 PDF。重复入库会复用已有条目。

读取限制：单文件 2 MiB、单次目录扫描最多 5000 文件／10000 条提交／约 64 MiB；JSON 临时文件和隐藏目录不参与扫描。达到限制或遇到坏记录时会提示，原始数据不删除。较大的长期池可由发布方归档旧批次。
