# 浏览浮层白屏：原生网页的画面接替（#4）

## 根因

浏览网页使用独立原生子 WebView，应用菜单则在主 WebView 的 DOM 中。后者的 `z-index` 无法超过前者；旧机制通过 `browse_bounds(visible=false)` 隐藏整个网页来露出菜单，因此看起来像白屏。PDF / Markdown 阅读器属于主 WebView DOM，没有这条原生层级限制。

先前只修复了 tooltip 和布局按钮 hover 自动展开；主动点击菜单仍会白屏。本次继续处理原生视图与应用浮层的显示交接。

## 修复

1. Windows WebView2 `CapturePreview` 截取当前可见页面；前端先完成 PNG 解码和绘制，再隐藏原生层。恢复时顺序反过来，不导航、不重新加载页面。
2. 串行 presentation 控制器协调截图、解码、显隐和释放；过期截图不落地，卸载立即隐藏，effect 实例各自持有画面所有权，防止旧回调修改新画面。恢复 IPC 失败保留截图并有限重试。
3. 补齐 Toast、Dialog / Sheet 遮罩和公共 `ViewportFloating` 检测；非模态注册不再全局隐藏浏览页，透明 / 不可见的浮层不再错误遮挡。拖拽失焦解除拖拽标记。
4. 浮层候选仍缓存，几何逐帧检查；只在连续遮挡开始时截图，结束释放，不在空闲时轮询截图。

## Windows 实测（2026-10-15）

真实 Tauri 开发窗口 / WebView2，Cool Papers 页面，CDP 输入与真实 IPC：

| 场景 | 结果 |
|---|---|
| 点击布局菜单、Agent 菜单 | 原生层隐藏前已有解码画面；菜单与网页同屏可见 |
| 添加网站 Dialog | 遮罩与弹窗正常显示，底下保留网页；Esc 恢复 |
| 页签右键菜单 | 同样完成画面接替，Esc 恢复 |
| 相交的长 Toast | Toast 可见且网页保留；消失后恢复。较短且不相交的 Toast 不触发截图 |
| 派发 dragstart / dragend | 开始后保留画面，结束后恢复；这是拖拽状态链路验证，不替代完整跨窗拖拽验收 |
| 截图响应人为延迟 500ms，菜单立即关闭 | 晚到结果被丢弃，没有发送隐藏指令，没有残留截图 |

该组 1079×700 页面 PNG data URL 约 46 KB，原生截图 IPC 约 41–62ms；只代表此开发窗口与页面，不代表所有页面 / 显示器上的开销。实际主视图截图确认菜单下面是网页内容，而不是纯色占位。

自动回归覆盖：先绘制后隐藏、先恢复后清帧、重叠浮层复用、过期截图丢弃、解码期间卸载、截取失败限频与恢复、恢复 IPC 重试、非模态和不可见浮层、tooltip 与候选缓存。

另覆盖截图期间标签切走立即隐藏，以及连续 resize 复用正在取得的帧（不逐帧重截，避免拖拽期间一直等不到接替）。14 项相关前端测试、8 项 browse Rust 测试、TypeScript、针对性 Biome、严格 Clippy 和生产构建通过；生产构建仍有既有的大 chunk 提示。

## 限制

Windows 上覆盖期间呈现静态帧，网页视觉更新和鼠标操作暂时停止；截取失败回退为隐藏。macOS / Linux 尚无接替实现，保留旧避让行为。后续原生实时叠放需要平台专项设计和实机验证。
