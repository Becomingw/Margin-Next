# 审阅工作区（Review Workspace）

`reviews/<id>/` 与 `papers/<id>/` 平级：用于待审论文（投稿审稿、合作者修改稿、自撰手稿）的 **常开行内修订 + 右侧跟随式批注气球 + 双模 PDF/正文对照**。

## 1. 与论文阅读平级的导航与入库

- **文件树表现**：
  - 顶层 `reviews/` 拥有专属的语义根目录图标（`ObjectIcon kind="reviews"`），默认展开；与 `papers/`、`notes/` 一样受系统保护，禁止删除、重命名、剪切或移动。
  - 每个审阅单元 `reviews/<id>` 在文件树中作为**收起的叶子条目**（`ReviewTreeRow`）渲染，显示论文标题与待处理批注数，不暴露内部 `review.json` / `manuscript.md` / `revisions/`，点击即直接进入审阅工作区。
- **待审论文导入**：
  - 支持导入本地 **PDF / Markdown / TeX**（右键 `reviews/` →「导入待审论文…」、拖拽文件到 `reviews/`、左上角魔棒弹窗或论文库表头的导入按钮）。
  - 导入 PDF 待审论文时，自动落盘 `<id>.pdf` 并在后台调用 PDF 正文解析引擎生成 `manuscript.md` 与配图，将解析出的正文设为初始基线（`r0`），无需手动复制文本。
- **论文库（Library）混排与筛选**：
  - 审阅条目与阅读论文同表展示，标题前带青色「审阅」徽标与待处理批注计数。
  - 表头提供 `全部 | 阅读 | 审阅` 分段筛选，点击审阅行直接打开审阅视图。

## 2. 类 Office Word 的审阅交互

Margin 的存储适配通过 `src/lib/review/api.ts` 注入，详见 [事务后端](../backend/margin.md)。
单处裁决先在隔离编辑树中生成候选，由 Host 校验版本 / 修改范围并提交后再刷新正文；
无法定位的选区明确失败，不把“单处”降级成“整稿”。候选保留 frontmatter，重复文字以段落和偏移消歧。
等待裁决期间正文临时只读，防止回执回来时覆盖新输入；上游 Edda 的文件型适配仍可独立使用。

独立 Margin 标题栏的「AI 审阅」提供显式 MCP 授权和待处理提案预览。一次授权固定到当前稿件；
切换稿件 / 工作区会撤销旧连接。「作为修订应用」只把提案写入正文，不自动接受基线；
草稿脏时禁止应用，旧 base 的提案提示重提。AI 和作者共用已有批注 / 回复卡片，AI 署名不可由客户端冒充。
完整使用与安全边界见 [单 AI checkpoint](../margin-single-ai.md)。

渲染与刷新（所见即所得）：

- 批注／修订范围按端点的最近公共祖先建立索引，每个范围只注入一次，由 Slate 向后代裁剪传播。每个索引桶记住计算时的节点：未改动的段落在编辑其它段落时保留痕迹，改动或移动过的节点不沿用旧范围。快照写入插件选项后显式 `redecorate`，否则 Plate 不会重新装饰。
- 正在输入的段落由插件在 Slate 自身渲染中按其对齐的基线段落即时计算修订、AI 归属与批注高亮，输入即见痕迹；全文重算等输入停顿约 400ms 再执行。浏览器原生插入字符时若另起一轮渲染重新切分该段文本，会把光标留在段首，因此段内输入不在额外一轮里重切；IME 组字期间也不重算。结构编辑、Agent 写入、批注变化与显示模式切换在同一帧应用；单次全文重算超过约 8ms（超长稿件）时改为短暂防抖，未改动段落的痕迹保持不变。
- 段落对齐：先去掉首尾相同段落，再对中间段做 LCS 精确匹配，匹配之间的剩余段按相似度配成修改，否则记为删除／新增。连续删除多段、删除最后一段都显示为原位置的删除线段落（字号跟随正文，不随下一段标题放大）；段末删除显示在最后一个字之后。多个相邻改动词之间只隔空格时合并成一处「整句删除 + 新句」，不再逐词交错；删除文字挂在一字符载体上，跨粗体等文本节点也只显示一次。
- 批注范围像 Word 一样随编辑移动（`src/lib/review/comment-ranges.ts`）：每条已定位的批注在编辑器里持有一个 Slate range ref，Slate 在每次编辑时移动它；改了引文里的字，该范围内的新文字就是新引文，全文重算时立即用于高亮与卡片定位，自动保存时随 `saveReviewManuscript(..., anchors)` 与正文一起写入（`review_save_manuscript`，见 [backend/review.md](../backend/review.md#写入与并发)），因此不会变成「已过时」。引文整段被删（范围变空）时不移动，仍按过时处理。从磁盘重载只替换改动的块（见 [markdown.md](markdown.md) 数据流），这些块里的 ref 随之清掉，批注按（可能已被 Agent 改写的）引文重新定位；其余块里的批注范围不受影响。
- 批注卡片默认紧凑：上方为作者 / 时间，下方为弱底引文与三行正文，有回复时只显示「N 条回复」，不显示操作栏；点卡片、点正文中的批注高亮或用功能区跳转到它即成为「选中」批注（`selectedCommentId`），完整展开回复、回复框与操作栏，点正文其它位置取消。悬停只联动高亮，不改变卡片大小。卡片 `memo`，卡片高度由一个 ResizeObserver 跟踪；常驻卡片不加阴影。
- 批注卡片：选中后点正文编辑，显式「保存」或 ⌘/Ctrl+Enter 提交、Esc 取消；保存失败时保留输入与编辑状态，不因失焦丢掉草稿。回复框带「取消」「回复」按钮，⌘/Ctrl+Enter 同样发送，普通回车换行；输入法组字时不触发发送快捷键。回复失败时保留草稿，只追加，不受 Agent 在同一线程并发回复影响。悬停回复显示操作图标：自己的回复可编辑（编辑过标「已编辑」）；任意回复（含 AI 的）都可删除，需在条目内再确认一次，删除后直接移出线程。AI 的回复只能由该 AI 通过 MCP 编辑。
- 编辑器分块渲染后（见 [markdown.md](markdown.md#长文档渲染)），只精确测量已绘制分块里的引文（`checkVisibility({ contentVisibilityAuto: true })`）：被跳过的分块只占占位高度，WebKit 却仍按完整排版报告其中文字的位置，落在别的分块上。其余批注按「所在分块位置 + 上次测得的块内偏移」放置，分块绘制（`contentvisibilityautostatechange`）或尺寸变化时重新测量。跳到未绘制的批注时，先把它所在的分块滚入视口，等其绘制、滚动锚定吸收新高度后（再过一帧）按精确位置定位。
- 气球与跳转位置按批注引文的文本范围（`toDOMRange`）测量，不依赖装饰是否已绘制，并按编辑器滚动区（编辑工具栏之下）的实际顶边与批注栏对齐。
- 批注栏排版（`src/lib/review/balloon-layout.ts`）：卡片按引文高度排列，重叠时下移；有正在撰写的草稿或选中批注时，它与引文对齐，上方卡片上移、下方卡片下移，密集处不再把后面的卡片一路推离原文；卡片不会越过批注栏顶端。

- **顶部集成审阅功能区（Review Ribbon）**：
  - **视图切换**（含 PDF 的审阅条目）：`正文审阅` | `双栏对照`（左 PDF 右正文审阅）| `PDF`。
  - **修订常开，显示可切换**：编辑始终记录修订；「显示修订」用绿色下划线展示插入、红色删除线展示删除，「最终文本」仅显示当前正文。「原始文本」是本轮对比基线的独立只读预览，不是历史上不可变的最初导入版本；主编辑器继续挂载与自动保存，切换不把基线写回正文。前两种模式保留修订计数及上一处／下一处、基线管理和还原操作，原始文本中不提供正文裁决。保存未完成时裁决按钮禁用，避免基于旧保存快照确认基线。
  - **跳转**：AI 计数（✦）连同上下箭头按文中顺序遍历 AI 修订与待处理的 AI 批注；批注计数连同上下箭头遍历待处理批注。跳到批注时若批注栏已收起会自动展开。
  - **AI 新内容提示**：打开审阅后新到的 AI 批注、回复或正文修改显示为「N 条新 AI 批注 · N 处新 AI 修改」，点击跳到第一条新批注或这些新修改写出的位置并清除提示；新 AI 批注卡片带品牌色细环。
  - **批注栏开关**：功能区最右侧按钮显示／收起批注栏（与阅读论文的批注栏一致）；收起时正文占满宽度，点击正文中的批注高亮会重新展开。
  - **批注与引用**：`新建批注`（对当前选区添加批注气球，不向 Markdown 注入 `^block-id` 噪音；气球按编辑器保存的选区定位，点选区浮动菜单时浏览器选区已被清掉，不能读 `window.getSelection()`）、`引用`（从论文库选择文献插入可外传的 `[@citekey]` 或 `(Author, Year)`）。
  - **逐处导航与基线管理**：`上一处修订` / `下一处修订` 只遍历正文修订；「接受此处修订」保留这一处改动并停止与旧稿对比，「接受全部修订」以当前稿为新基线并开始新一轮；「拒绝此处修订」或「拒绝全部修订」将正文回退到对应基线内容。批注使用自己的回复、解决／重开流程，不参与这些正文操作。
  - **导出审阅**：一键导出包含结构化审阅意见 `REVIEW.md` 与正文的独立目录。
- **右侧跟随式批注气球（Floating Margin Balloons）**：
  - 批注气球按正文锚点纵坐标防重叠排布（`top = max(anchorY, prevBottom + 10)`），随正文滚动直接平移；选中的修订也可显示一张前后对照卡片，带作者及接受 / 拒绝按钮。只测量选中的一处修订，不为每处差异创建卡片；长稿不会因修订数量产生大量气球。正文有独立阅读宽度，功能区可换行；正文容器不足 48rem 时，审阅栏移到底部并独立滚动，不挤压正文，且不画跨区引线。
  - 悬停或选中批注时，从引文末尾沿行画虚线引线到对应卡片（AI 批注为品牌色），卡片因防重叠被挤开时也能看出指向哪段文字。
  - 不在正文中的批注（PDF 页面批注、引文已删除或无法定位）不再按虚构高度混在气球里，而是收在栏头「N 条不在正文中」下拉中。栏头另有全部／待处理筛选与收起按钮。
  - 默认显示全部未删除批注，解决后卡片留在原处且可重新打开；栏头显示当前筛选，可切换为仅显示待处理批注。修订与待处理批注计数分开。单处拒绝在 Plate 中局部还原并自动保存，不重载整篇稿件。滚动时不重算全文差异或 React 重绘正文。

## 3. Agent 审阅上下文

修订是当前正文相对本轮基线的差异，批注是带锚点的讨论；两者都用于与 Agent 交流，不要求逐处确认。Agent 可通过只读 MCP `review_read` 获取批注及完整回复，`review_changes` 获取可分页的本轮正文差异，`review_manuscript` 获取当前正文。纳入基线仅改变对比起点，还原会修改正文；精简模式只隐藏修订痕迹，不会清除传给 Agent 的差异。

MCP 可直接创建 / 导入审阅稿、解析 PDF、管理批注、按原文和校验哈希改写正文及导出；MCP 不可确认修订或移动比较基线。行内颜色统一表达修改类型（绿色插入、红色删除），不再用作者颜色区分增删；AI 批注 / 修订卡片和回复标注写入它的 Agent 名（Claude Code、Codex 等，旧记录显示「AI」），行内 AI 修订悬停显示「Agent 名 修订」。多个 Agent 同审时据此区分彼此的批注与修改：

- **每个 Agent 一种身份色**：按 Agent 首次写入本审阅的顺序，从对象图标色板（紫、蓝、青、玫红、石板、铜）依次分配（`src/lib/review/agents.ts`），同一审阅内不重复、整个审阅期间不变；卡片署名、回复署名、Agent 菜单与引线使用这一色（`--agent`），未署名的旧 AI 记录用品牌色。行内增删始终使用 `review-insert` / `review-delete`；批注高亮使用 `review-comment`，类型和身份不混用。
- **Agent 菜单**：功能区 ✦ 按钮列出参与本审阅的 Agent 及各自颜色、未决修改数与待处理批注数。选中某个 Agent 后只显示它的修订痕迹（其他人的修订按精简模式隐藏）和它写过或回复过的批注线程，上下箭头也只在它的内容间跳转；选「全部 Agent」恢复。来源随 `review.json` 事件保存，确认新一轮后旧轮的修订痕迹不再显示。相同文本或同一位置被反复改写时，按当前仍可唯一定位的最后写入来源显示，无法可靠归属的差异保持默认样式。修改记录存的是 Markdown 源码，与编辑器文字比对前去掉强调符号并还原转义（`\[1]` → `[1]`）；改动大到按整段替换显示时，只要这次修改写下的文字仍在该段中并占其大半，整段归给它。一次修改改写了多段时按段拆开定位：首段带修改前文、末段带修改后文，中间整段按原文匹配。

Markdown 强调标记不属于编辑器可见正文，标点删除也可能被段落差异合并为替换；来源匹配需结合去除边缘格式标记后的上下文与实际被删字符，避免把这类 AI 修订显示成人工修订。

AI 归属以「写入区间」为准：按编辑事件写入的文字和保存的前后文在当前段落中唯一定位（两侧上下文都须仍在），再扩展到词边界（Host 记录时会把与旧文共享的字符留在上下文里，如 model|s）；区间内的每处差异都归该次编辑。被删整段只按被删文字匹配。无法唯一定位时退回原有的精确文本匹配，且「唯一删除」规则只接受确实删掉了该段文字的事件，避免作者在别处的一次退格把 AI 删除改记为人工。

外部刷新：Watcher 报告打开中的审阅单元 `review.json` 变化时，按单元约 80ms 合并后先取 `review_state_stamp`，与最后一次收到的视图相同（自身写入的回声）就到此为止；否则重新读取（同一单元同时只发一次请求，期间的变化再读一次，基线正文按哈希沿用），内容签名不变则不触发重绘，因此 AI 批注、回复与本轮改动会立即出现。`manuscript.md` 变化照常经编辑器原地重载；普通编辑器重载在窗口失焦时会暂缓到回到前台，但打开中的审阅稿在窗口可见时也会立即重载，方便在其它应用中驱动 Agent 时同步查看。

正文中被删除的批注引文显示「已过时」，从待处理计数及「待处理」筛选中排除；批注讨论仍保留在「全部」中，若引文恢复可重新附着。此标记由锚点状态决定，不擅自将讨论设为「已解决」；PDF 页码批注不受正文回退影响。
